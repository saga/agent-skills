# 领域建模自动化引擎（Domain Modeling Engine）

## 一、核心定位

该技能用于：

> 自动识别、构建和演化领域模型，而不是简单的数据存储。

它强调：

-   领域概念抽象
-   实体与值对象区分
-   聚合与边界识别
-   不变式表达
-   关系语义建模
-   结构版本演化

数据库只是持久化手段，而不是目标。

------------------------------------------------------------------------

## 二、设计原则

### 1️⃣ 领域优先（Domain First）

模型表达的是：

-   业务语义
-   约束规则
-   生命周期
-   关系语义

而不是：

-   CRUD 结构
-   表结构设计

------------------------------------------------------------------------

### 2️⃣ 聚合意识（Aggregate Awareness）

该技能不仅抽取实体，还会：

-   识别可能的聚合根
-   分析实体间依赖方向
-   识别跨聚合引用
-   推断事务边界

------------------------------------------------------------------------

### 3️⃣ 不变式驱动（Invariant Driven）

支持自动识别和建模：

-   Validation Rules
-   Business Constraints
-   Domain Invariants
-   Lifecycle Transitions

所有规则都与实体或聚合显式绑定。

------------------------------------------------------------------------

### 4️⃣ 模型可演化（Model Evolvable）

领域模型支持：

-   版本化管理
-   结构 Diff
-   变更审计
-   聚合边界变化分析
-   向前兼容性检测

------------------------------------------------------------------------

## 三、核心能力

### 1️⃣ 领域概念抽取

支持从以下输入中自动抽取结构化领域概念：

-   TypeScript / Java / Python 类定义
-   API Schema
-   PRD 文档
-   数据表结构
-   业务说明文本

可识别：

-   Entity
-   Value Object
-   Enum
-   Aggregate
-   Domain Service

------------------------------------------------------------------------

### 2️⃣ 关系语义识别

不仅识别结构关系：

-   1:1
-   1:N
-   M:N

还识别语义关系：

-   ownership
-   composition
-   reference
-   dependency
-   lifecycle coupling

------------------------------------------------------------------------

### 3️⃣ 聚合推断

通过分析：

-   外键方向
-   修改频率
-   不变式作用范围
-   事务边界
-   生命周期依赖

推断：

-   候选聚合根
-   聚合边界
-   跨聚合引用风险

------------------------------------------------------------------------

### 4️⃣ 规则建模

支持抽取并建模：

-   业务规则
-   校验规则
-   领域不变式
-   生命周期状态机
-   约束表达式

并与实体或聚合强绑定。

------------------------------------------------------------------------

### 5️⃣ 模型输出能力

可导出为：

-   JSON 领域 DSL
-   Mermaid ER 图
-   OpenAPI Schema
-   Graph Schema
-   结构变更报告
-   聚合边界分析报告

------------------------------------------------------------------------

## 五、适用场景

### ✅ 适用

-   企业级领域模型构建
-   遗留系统反向抽象
-   DDD 实践辅助
-   架构治理
-   多团队领域对齐
-   结构一致性检测
-   聚合边界分析
-   领域模型版本对比

### ❌ 不适用

-   仅做数据存储
-   仅做 CRUD 生成
-   仅做 RAG 问答系统
-   仅做图数据库查询工具

------------------------------------------------------------------------

## 六、理论基础

该引擎的理论基础源自：

-   《Domain-Driven Design》------ Eric Evans

核心概念包括：

-   Entity
-   Value Object
-   Aggregate
-   Bounded Context
-   Invariant
-   Domain Service

本技能旨在自动化支持 DDD 实践，而非替代架构设计思考。

------------------------------------------------------------------------

## 七、战略定位

这不是：

> 轻量图数据库方案

也不是：

> SQLite 建模脚手架

而是：

> 企业级领域抽象与建模自动化引擎

------------------------------------------------------------------------
