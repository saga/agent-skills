# 文件系统即新数据库：我如何为 AI 代理构建个人操作系统

每一次 AI 对话都以相同的方式开始。你解释你是谁。你解释你正在做什么。你粘贴你的风格指南。你重新描述你的目标。你给出昨天、前天、大前天都给出过的相同上下文。然后，40 分钟后，模型忘记了你的声音，开始写得像新闻稿一样。

我厌倦了这种情况。所以我构建了一个系统来解决它。

我称之为**个人大脑操作系统（Personal Brain OS）**。它是一个基于文件的个人操作系统，存在于 Git 仓库中。克隆它，在 Cursor 或 Claude Code 中打开，AI 助手就拥有了一切：我的声音、我的品牌、我的目标、我的联系人、我的内容管道、我的研究、我的失败。没有数据库，没有 API 密钥，没有构建步骤。只有 80 多个 Markdown、YAML 和 JSONL 文件，人类和语言模型都能原生读取。

---

## 1) 核心问题：上下文，而非提示词

大多数人认为 AI 助手的瓶颈在于提示词。写更好的提示词，得到更好的答案。这对于单次交互和生产级代理提示词来说是正确的。但当你希望 AI 在数周和数月内跨数十个任务像你一样运作时，这就行不通了。

### 注意力预算

语言模型有有限的上下文窗口，而且并非所有部分都是平等的。这意味着将你所有知道的东西转储到系统提示词中不仅是浪费，它还会主动降低性能。你添加的每个 token 都在竞争模型的注意力。

我们的大脑工作方式类似。当某人在会议前向你简要介绍 15 分钟时，你记得他们说的第一件事和最后一件事。中间部分模糊了。语言模型有相同的 U 形注意力曲线，只是他们的是数学上可测量的。Token 位置影响回忆概率。新模型在这方面正在改进，但你仍然在分散模型对最重要事情的注意力。知道这一点会改变你为 AI 系统设计信息架构的方式。

### 渐进式披露

这是使整个系统工作的架构模式。系统不是一次性加载所有 80 多个文件，而是使用三个级别：

- **第 1 级**是一个轻量级路由文件，始终加载。它告诉 AI 哪个模块是相关的。
- **第 2 级**是仅在需要该模块时加载的模块特定指令。
- **第 3 级**是仅在任务需要时加载的实际数据（JSONL 日志、YAML 配置、研究文档）。

这反映了专家如何运作。三个级别创建了一个漏斗：广泛路由，然后模块上下文，然后特定数据。在每一步，模型都有它需要的，没有更多。

我的路由文件是 `SKILL.md`，它告诉代理"这是一个内容任务，加载品牌模块"或"这是一个网络任务，加载联系人"。模块指令文件（`CONTENT.md`、`OPERATIONS.md`、`NETWORK.md`）每个 40-100 行，包含文件清单、工作流序列和带有该领域行为规则的 `<instructions>` 块。数据文件最后加载，仅在需要时。AI 从 JSONL 逐行读取联系人，而不是解析整个文件。三个级别，最多两次跳转到任何信息片段。

## 2) 文件系统作为内存

我做出的最反直觉的决定之一：没有数据库。没有向量存储。除了 Cursor 或 Claude Code 的功能外，没有检索系统。只有磁盘上的文件，用 Git 版本控制。

### 格式-功能映射

系统中的每个文件格式都是根据 AI 代理如何处理信息而选择的：

- **JSONL 用于日志**，因为它按设计是追加-only 的，流式友好的（代理逐行读取而不解析整个文件），每行都是自包含的有效 JSON。
- **YAML 用于配置**，因为它干净地处理层次数据，支持注释，对人类和机器都可读，没有 JSON 括号的噪音。
- **Markdown 用于叙述**，因为 LLM 原生读取它，它在任何地方都能渲染，在 Git 中产生干净的差异。

### 情景记忆

大多数"第二大脑"系统存储事实。我的也存储判断。`memory/` 模块包含三个追加-only 日志：

- `experiences.jsonl` - 关键时刻，带有 1-10 的情感权重分数
- `decisions.jsonl` - 关键决策，带有推理、考虑的替代方案和跟踪的结果
- `failures.jsonl` - 出了什么问题、根本原因和预防步骤

拥有你的文件的 AI 和拥有你的判断的 AI 之间是有区别的。事实告诉代理发生了什么。情景记忆告诉代理什么重要、我会做得不同的事情，以及我如何思考权衡。当代理遇到与我记录的决策相似的决策时，它可以参考我过去的推理，而不是生成通用建议。失败日志是最有价值的，它编码了需要真正痛苦才能获得的模式识别。

### 跨模块引用

系统使用平面文件关系模型。没有数据库，但结构化到代理可以跨文件连接数据。`interactions.jsonl` 中的 `contact_id` 指向 `contacts.jsonl` 中的条目。`ideas.jsonl` 中的 `pillar` 映射到 `identity/brand.md` 中定义的内容支柱。书签提供内容想法。帖子指标提供每周回顾。模块对加载是隔离的，但对推理是连接的。

没有连接的隔离只是一堆文件夹。跨引用让代理在需要时遍历知识图谱。"为我和 Sarah 的会议做准备"触发查找链：在联系人中找到 Sarah，拉取她的互动，检查涉及她的待办事项，编译简报。代理跨模块跟踪引用而不加载整个系统。

## 3) 技能系统：教 AI 如何做你的工作

文件存储知识。技能编码流程。我按照 Anthropic Agent Skills 标准构建了 Agent Skills，结构化指令告诉 AI 如何执行特定任务，内置质量门。

### 自动加载 vs 手动调用

两种类型的技能解决两个不同的问题：

- **参考技能**（`voice-guide`、`writing-anti-patterns`）在 YAML frontmatter 中设置 `user-invocable: false`。代理读取描述字段，每当任务涉及写作时自动注入它们。我从不动用它们，它们每次静默激活。

- **任务技能**（`/write-blog`、`/topic-research`、`/content-workflow`）设置 `disable-model-invocation: true`。代理不能自己触发它们。我输入斜杠命令，技能就成为代理该任务的完整指令集。

自动加载解决一致性问题。我不必每次要求草稿时都说"使用我的声音"。系统为我记住。手动调用解决精确性问题。研究任务与博客文章有不同的质量门。保持它们分开防止代理混淆两个不同的工作流。

### 语音系统

我的声音被编码为结构化数据和一些氛围。语音配置文件在 1-10 的量表上评分五个属性：

- 正式/随意 (6)
- 严肃/ playful (4)
- 技术/简单 (7)
- 保守/表达 (6)
- 谦逊/自信 (7)

反模式文件包含三个层级的 50+ 禁用词、禁用开头、结构陷阱（强制三法则、系动词避免、过度对冲），以及每段一个破折号的硬限制。

大多数人用形容词描述他们的声音："专业但平易近人"。这对 AI 没用。技术/简单量表上的 7 告诉模型确切落在哪里。禁用词列表更强大；定义你不是什么比定义你是什么更容易。代理根据反模式列表检查每份草稿并重写任何触发它的内容。结果是听起来像我的内容，因为护栏防止它听起来像 AI。

每个内容模板每 500 字包含语音检查点："我是否以洞察为先？我是否用数字具体？我实际上会发布这个吗？"博客模板有内置的 4 遍编辑流程：结构编辑（钩子是否吸引人？）、语音编辑（禁用词扫描、句子节奏检查）、证据编辑（声明有来源吗？）和朗读测试。质量门是技能的一部分，不是我事后添加的。

### 模板作为结构化支架

五个内容模板定义不同内容类型的结构：

- **长文博客模板**有七个部分（钩子、核心概念、框架、实际应用、失败模式、入门、结尾），每部分有字数目标，总计 2,000-3,500 字。
- **线程模板**定义 11 帖结构，包含钩子、深度挖掘、结果和 CTA。
- **研究模板**有四个阶段：格局映射、技术深度挖掘、证据收集和差距分析。

模板不仅约束创造力，还约束混乱。没有结构，代理产生无定形的文本块。有结构，它产生有节奏、进展和回报的内容。每个模板还包括质量检查清单，所以代理可以在展示草稿前自我评估。

研究模板输出到 `knowledge/research/[topic].md`，格式结构化：执行摘要、格局图、核心概念、证据库（统计数据、引用、案例研究、论文，每个都标注来源和日期）、失败模式、内容机会和来源列表（按 HIGH/MEDIUM/LOW 分级可靠性）。该研究文档然后输入博客模板的大纲阶段。一个技能的输出成为下一个的输入。管道自我构建。

## 关键要点

1. **上下文工程 > 提示工程** - 为 AI 设计信息架构，而不是写更好的提示词
2. **渐进式披露** - 三级加载系统优化注意力预算
3. **文件即数据库** - JSONL + YAML + Markdown 的组合足够强大
4. **技能即流程** - 将重复任务编码为可复用的 Agent Skills
5. **语音即数据** - 将个人风格量化为可配置的参数
